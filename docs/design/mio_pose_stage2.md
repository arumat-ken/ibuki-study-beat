## 2. 腕の切り出し（透過PNG）

`apps/mio_call/tools/cut_arms.py`（Python 3、`pip install pillow numpy`）。

```bash
python3 cut_arms.py --src reference/gestures/palm_up/generated-upper.png \
                    --config reference/gestures/palm_up/arms.json \
                    --out reference/gestures/palm_up/
```

- `arms.json`（`arms.example.json` を複製）に、腕の範囲を**元画像のピクセル座標の多角形**で書く
  （または白＝腕のマスク画像）。**自動検出はしません。** 腕は胴の前にあり服と同じ色になりうるので、
  境界を自動で決めると黙って誤ります。
- **`right-arm.png` = 本人の右手 = 画面の左、`left-arm.png` = 本人の左手 = 画面の右。**
  切り出した形の重心が正しい側にないと、エラーで止まります。
- 割合（0..1）で書いた座標は、エラーで止まります（x は幅比・y は高さ比で、混ぜると1.5倍ずれるため）。
- 出力：`right-arm.png`、`left-arm.png`、`arms_meta.json`（元画像での位置・肩と手首のアンカー・重心・面積）、
  `arms_preview.png`（元画像に輪郭を重ねたもの。赤＝本人の右、青＝本人の左）。
- 機械検査は、左右の側、空でないこと、塊が1つであること、端に接していないことだけです。
  **指の本数・親指と小指の向きは見ていません。** `arms_preview.png` を目で確認してください。

### 検証したこと／していないこと
- **検証した**：合成した画像（本物の絵ではない）で、正常系、左右を入れ替えた設定（止まる）、
  割合の座標（止まる）の3つ。RGBA で出力され、左右の輪郭が画面の左右に出ること。
- **未検証**：本物の `generated-upper.png`。本物の絵での縁の見え方、羽根の幅（`feather`）の適否。

### 重大な注意：土台の絵に腕があるか
`generated-upper.png` から腕を切り出して**土台の上に重ねる**場合、土台の同じ位置に腕が描かれていると、
**腕が二重に見えます**（顔で起きた二重写しと同じ原因）。土台側の腕の部分を消した「クリーンプレート」が要ります。
これは、元の絵を見ないと判断できないので、確認項目に入れておきます。

## 3. 第2段階（残り5ポーズ）の骨格ガイド

定義：`apps/mio_call/tools/pose_defs_stage2.json`、計算と描画：`apps/mio_call/tools/pose_guides.py`、
出力例：`docs/design/pose_guides_stage2/`（`contact_sheet.png` ほか）。

```bash
python3 pose_guides.py --defs pose_defs_stage2.json --out guides_out
```

- 座標は**肩幅=1 の単位**、原点は両肩の中点（ピクセルではない）。実際の `pose-guide.png` に合わせるときは、
  そのガイドの肩幅(px)で置き換える。
- 腕は「肩→肘→手首」の骨の長さを固定（上腕0.72・前腕0.56・手0.42）。**手首の目標から肘を逆算**するので、
  骨の長さは必ず保たれ、届かない位置はエラーになる。
- **数値は標準的な人体比から置いた初期値で、確定済みの palm_up のガイドとは未照合です。**
  palm_up の肩幅・手の大きさを測り、`limits` を合わせてから使ってください。

| ポーズ | 動く腕 | 手首（SW） | 指の指定 | 親指 / 小指（画面上） |
|---|---|---|---|---|
| `wave` 手を振る | 本人の右（画面左） | (-0.80, 0.10) | 5本を軽く開く、手のひら正面 | 親指＝中心側、小指＝外側 |
| `point_self` 自分を指す | 本人の右 | (-0.35, 0.62) | 人差し指のみ胸の中央へ。他は握る | 親指＝上、小指＝下 |
| `index_up` 要点を示す | 本人の右 | (-0.66, 0.22) | 人差し指を上へ。他は握る、手のひら正面 | 親指＝中心側、小指＝外側 |
| `think_finger` 考える | 本人の右 | (-0.36, 0.12) | 人差し指を頬の横に。他は軽く曲げる | 親指＝見えない、小指＝下 |
| `gassho` 両手を合わせる | **両手** | R(-0.07, 0.78) / L(+0.07, 0.78) | 5本そろえて上へ、手のひら同士 | 親指＝奥で見えない、小指側が手前 |

もう一方の腕は、土台の絵の腕をそのまま使う想定（`"mode": "base"`）。

### palm_up の基準（親指＝外）は、他のポーズに持ち込めない
手のひらの向きが変わると、親指の側が変わります。右手で手のひらを正面に向けて上げる（`wave`、`index_up`）と、
親指は体の中心側です。手のひらを合わせる `gassho` では、親指は胸に近い奥で、正面からは見えません。
**「両親指は外側」を全ポーズの合格基準にすると、正しい絵を落とします。**
上の表は、右手の構造から手で導いたものです。**実際の絵では未確認**なので、最初の生成結果で確かめてください。

### 既知の限界
- 2Dの固定長なので、**手前に出る腕（palm_up、think_finger）の奥行きによる短縮は表せません。**
  `think_finger` は骨格図では肘が深く折れて見えます。このポーズは骨格図でなく、絵で判断してください。
- `gassho` は左右の手が重なるので、切り出しは x=0 の線で分けるか、1枚の「合わせ手」として生成する案もあります。
  どちらにするかは未決です。

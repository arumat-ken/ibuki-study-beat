# 依頼：ブラウザだけで動く音声会話アシスタント「澪（みお）」を作ってください

## 何を作るか

一枚の HTML ファイル（GitHub Pages で配信）。開くと女性キャラクター「澪」の
上半身が表示され、**画面に触れずに声だけで会話**できます。彼女は音声で返事をし、
その内容に応じて**口・目・眉が動きます**。

Zoom で一対一で話しているような画（上半身正面固定）が目標です。

## 絶対条件

1. **キー・トークン・秘密情報をリポジトリに書かない。** APIキーは実行時に
   利用者が画面から入力し、`localStorage` にのみ保存する。ソースにも、
   コミットにも、ログにも出さない。
2. **静的ファイルのみ。** サーバーを立てない。GitHub Pages で配信できること。
   ビルド工程なし、依存パッケージなし、`<script src>` は使わず1ファイルに収める。
3. **iPhone Safari と Mac Safari / Chrome で動くこと。** iPhone が主な利用環境。
4. 表示・UI の文言はすべて日本語。

## 構成

### 耳（音声入力）— ここが最重要

`SpeechRecognition`（Safari は `webkitSpeechRecognition`）を使う。

- `lang='ja-JP'`, `continuous=true`, `interimResults=true`
- **一度マイクを許可したら、あとは触らずに会話が続くこと。** 発言のたびに
  ボタンを押させてはいけない。これがこのアプリを作る理由そのもの。
- 認識が終わるたびに自動で再開する。iOS Safari は無音が続くと勝手に止まるので、
  `onend` で必ず再起動する。
- **`start()` を二重に呼ぶと `InvalidStateError` が飛ぶ。** 起動中フラグで守ること。

### 口（音声出力）

`speechSynthesis`、`lang='ja-JP'`。感情に応じて `rate` と `pitch` を変える
（端末の声には感情の指定ができないので、速さと高さでしか出せない）。

### 頭脳

既定は **Gemini API（`gemini-2.0-flash` などの無料枠モデル）**。
`fetch` で直接呼ぶ。キーは前述のとおり実行時入力・localStorage 保存。
キーが未入力なら、その旨を画面に出して文字入力だけで動くこと（落ちないこと）。

返事は **JSON で受け取る**：

```json
{ "reply": "返事の本文",
  "kana": "へんじのほんぶん",
  "emotion": "neutral|relaxed|happy|sad|angry|surprised",
  "strength": 0.0,
  "tears": 0.0 }
```

`kana` は口の形に使うので**必ずひらがな**で返させる。
性格は「落ち着いた聞き上手。返事は2〜3文で短く。」

## 顔のアニメーション（ここに既知の落とし穴が集中しています）

### 使う画像

同じ構図・同じ大きさで描かれた8枚。利用者が枠から選んで `localStorage` に保存する。

| 枠 | 中身 | 用途 |
|---|---|---|
| `base` | 通常（目を開けた顔） | 土台 |
| `eyeClosed` | 目を閉じた顔 | まばたき |
| `eyeSmile` / `eyeWide` / `eyeTear` | 笑う目 / 見開く目 / 潤んだ目 | 目の表情 |
| `browUp` / `browSad` / `browAngry` | 上げ眉 / 困り眉 / 怒り眉 | 眉の表情 |

合成のしかたは、**顔全体を差し替えるのではなく、目の帯・眉の帯だけを重ねる**。
そうすれば「困り眉 × 潤んだ目」のような組み合わせが実行時に作れる。

### 落とし穴①：半透明で重ねてはいけない（最重要）

表情の強さを**不透明度**で表そうとしないこと。

開いた目の絵50% ＋ 閉じた目の絵50% は、半分閉じた目には**なりません**。
**二重写し**になります。まぶたの線も眉の線も2本見える。実機で確認済みの不具合です。

**1コマには1枚の絵だけを、不透明度1で描く。**手描きアニメと同じくカットする。
量は「どの絵を出すか」を決めるものであって、透明度ではない。

強さは、連続的に変えて破綻しないものだけで表す：
首の傾き、拡大率、呼吸の速さ、頬の赤み、涙、返事が届いた瞬間の小さな動き。

同じ理由で、**「閉じた目を薄く重ねて目を細める」をやってはいけない。**
表情が続くあいだずっとまぶたが2組ある状態になる。細めた目には細めた目の絵を使う。

### 落とし穴②：帯の位置は単位を間違えやすい

目の位置（左右2点、画像に対する 0..1 の割合）から帯を計算する。
ここで、**x は画像の幅に対する割合、y は高さに対する割合**であることに注意。
目の間隔（x方向）をそのまま y 方向のオフセットに使うと、
3:2 の縦長画像では**1.5倍ずれます**。必ず `幅/高さ` を掛けて変換すること。

```js
function eyeGapY(){                      // 目の間隔を「高さに対する割合」に直す
  var a = base.width / base.height;
  return Math.abs(eyes.rx - eyes.lx) * a;
}
```

実測した位置（このキャラクターの顔に定規を当てた値）：

| | y | 目の線からの距離（目間隔） |
|---|---|---|
| 眉 | 0.252 – 0.272 | 上 0.17 – 0.29 |
| 目 | 0.283 – 0.315 | 上0.10 – 下0.11 |
| 目の線 | 0.298 | — |

これに合わせた帯（`sy = eyeGapY()`、`cy` は目の線）：

```js
brow = { y: cy - sy*0.42, h: sy*0.29 }   // 眉：目の線の上 0.13〜0.42
eye  = { y: cy - sy*0.13, h: sy*0.38 }   // 目：上0.13〜下0.25
```

2つの帯は 0.13 のところで**接し、重ならない**こと。重なると後から描いたほうが
相手の部位を塗りつぶす。

### 落とし穴③：目の位置を「重心」で自動検出してはいけない

`base` と `eyeClosed` の差分から目の位置を求めたくなるが、
**差が大きい点の重心**を左右それぞれで取る方式は壊れる。
「変わったのは目だけ」という前提が成り立たないため——
別々に生成した2枚は髪の流れも服のしわも違う。右下に暗い差分が1つあるだけで、
右半分の重心はそこへ引きずられる。実機で**左目 y0.301 に対し右目 y0.484**（傾き56%）
という結果になり、帯が総崩れして6枚中4枚が誤判定された。

正しくは、**目について分かっていること**を使う。目は2つあり、水平に並び、左右に1つずつある。

1. 差分を軽くぼかす
2. 各行を「左半分の変化量と右半分の変化量の**小さいほう**」で採点する
   （片側だけのかたまりでは点が上がらない。両目のある行だけが高得点になる）
3. 最良の行の前後だけを見て、左右それぞれの最大点とその周りの小さな重心を取る

さらに保険として、**左右の高さの差が間隔の25%を超えたら測定を拒否**し、
手で指定させる。悪い値を黙って使わないこと。

### 落とし穴④：口は音量ではなく「読み」で動かす

音量で口を開閉すると日本語では形が合わない。**`kana` を母音に変換**して、
あ・い・う・え・お・ん・閉じ の7つの形を作る。

- 小さい ゃゅょ は直前の音に乗せる
- 「ー」は直前の母音を伸ばす
- 「っ」と句読点は閉じる
- **開くのは速く、閉じるのは遅く**（開き 45ms / 閉じ 85ms の時定数）。
  左右対称にすると機械的に見える。

元の絵の口を隠してから描く。隠す範囲は口の位置から自動で測る
（**明るさの閾値ではなく、押された点からつながっている暗い領域を辿る**こと。
髪が黒いと閾値方式は髪を拾う）。

### 落とし穴⑤：音声の競合で無限ループ・例外になる

- `speechSynthesis.cancel()` は現在の発話の `onend` を発火させる。**正常終了と
  区別がつかない。**発話ごとに通し番号を持たせ、古い発話の終了は無視する。
- 話している最中に認識を始めると、iOS では音声セッションが再生中のまま失敗する。
  **必ず停止してから、350ms ほど置いて開始する。**
- **自分の声を聞いてしまう。**スピーカー使用時、彼女の返事をマイクが拾って
  そのまま送信し、延々と自問自答する。**話している間（と直後0.9秒）に
  入った認識結果は捨てる。**イヤホンなら起きないが、必ず実装すること。

## 画面

- 上半身が入る縦長のタイル（`aspect-ratio: 3/4`）に canvas で顔を描く
- 状態表示（待機中／聞いています／考えています／話しています）
- 会話のやり取りが残る欄
- 折りたたんだ設定欄：8枚の枠、口と目の位置合わせ、APIキー入力、マイク確認
- 文字入力欄も残す（音声が使えない環境の逃げ道）

配色は落ち着いたもの。ダークモードにも対応（`prefers-color-scheme`）。

## 完成の判定

1. iPhone で開き、**一度だけマイクを許可したあと、画面に触れずに3往復会話できる**
2. 彼女の声を拾って自問自答しない
3. 口が「読み」に合って動く（音量ではない）
4. 表情が変わったとき、**線が二重に見えない**
5. 8枚の絵を入れ替えても、目と眉の帯が正しい位置に来る

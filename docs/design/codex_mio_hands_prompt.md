## 作るもの

### 画面

縦長タイル（`aspect-ratio: 3/4`）に canvas。上半身の澪が正面固定で映る。
既存と同じ人物像・同じ構図。**顔の絵（base と7枚）はそのまま使う。**

### 描画順（厳守）

```
1. base（土台。不透明度1、半透明にしない）
2. 顔の帯（眉の帯／目の帯）。まばたきもここ
3. 頬の赤み・涙
4. 口（元の口を隠してから、読みに合う口の形を描く）
5. 手（前腕＋手）  ← 今回追加。必ず最後
```

手が顔より下の層なら、手が顔の前に来たとき顔が手を貫通して見える。**手は最後。**

### 手のスプライト

- 1ポーズ = 1枚の PNG（透過）。**前腕の途中から指先まで**。下端は切れていてよい。
- 画面の**下辺から入る**。手首〜前腕が画面の下端で見切れる位置に置く。
- 右手のみ用意し、**左手は左右反転で作る**（枚数を半分にする）。
  ただし反転で意味が変わるポーズ（指差し等）は、右手のみで使う。
- Gemini 生成の画像は緑背景（#00FF00）。実行時に**クロマキーで透過化**する：
  緑が優勢なピクセルのアルファを下げ、**縁の緑かぶりを除去（デスピル）**する。
  デスピルを省くと、肌の輪郭に緑の縁が出る。
- 手のスプライトを置いていない間は、**仮の手（ベクター描画の肌色の手）**で動くこと。
  絵が無くても落ちない。

#### ポーズ一覧

最初に作る（MVP）：

| 名前 | 意味・使いどころ |
|---|---|
| `wave` | 手を振る。あいさつ・別れ |
| `palm_up` | 手のひらを上に向けて差し出す。説明・提案・「どうぞ」 |
| `point_self` | 自分を指す。「わたし」「私が」 |
| `index_up` | 人差し指を立てる。「ひとつだけ」「ポイントは」 |
| `think_finger` | 指を顎や頬に当てる。考え中・迷い |
| `gassho` | 両手を合わせる。お願い・感謝・ごめん |

後で足す：`thumbs_up`、`fist_cheer`、`stop_palm`、`shrug`、`clap`、`cover_mouth`。

**`gassho` と `clap` と `shrug` は両手を使う。** 左右の手を別スプライトとして同時に出し、
胸の前で合わせる位置は較正で決める。

### 動きのルール（最重要）

1. **ポーズの切り替えは、手が画面外にいる間に行う。**
   手を見えたまま別のポーズ画像に差し替えない。
   「半透明で重ねて混ぜる」も禁止——二枚の手が重なる**二重写し**になる（顔で既知の不具合と同じ）。
   **1コマには1枚の絵だけを不透明度1で描く。**
2. 動きは**画像ではなく変換（位置・回転・拡大）で作る**。連続量なので破綻しない：
   - 登場：下から上へ 280〜420ms、`easeOutCubic`
   - 手ぶり中：手首あたりを支点にした小さな回転（±6°程度）と上下（呼吸）
   - 退場：下へ 240〜360ms、`easeInCubic`
   - `wave` は回転を往復（周期 ~0.5s、3〜4回）
3. 手が出ている間も、**顔の表情・口・まばたきは止めない。**
4. 同時に出す手ぶりは1つだけ。次の手ぶりは、前の手が退場してから。
5. 返事が終わったら、手は必ず退場して初期状態（画面外）に戻る。
   エラーや中断（`speechSynthesis.cancel()`）でも戻ること。**手が出たまま固まる状態を作らない。**

## 手ぶりの指示（Gemini の返事 JSON を拡張）

現行の返事 JSON に `gestures` を足す。**無くても動くこと**（後方互換）。

```json
{ "reply": "返事の本文",
  "kana": "へんじのほんぶん",
  "emotion": "neutral|relaxed|happy|sad|angry|surprised",
  "strength": 0.0,
  "tears": 0.0,
  "gestures": [
    { "pose": "wave", "at": 0.0 },
    { "pose": "palm_up", "at": 0.55 }
  ] }
```

- `at` は返事本文の**0〜1の位置**（0=冒頭、1=末尾）。
- システムプロンプトに追記する指示：
  「手ぶりは返事1つにつき0〜2個。無理に付けない。あいさつと別れには wave、
  説明や提案には palm_up、自分のことを言うときは point_self、要点を示すときは index_up、
  迷いや考えには think_finger、お願い・感謝・謝罪には gassho。
  使えるポーズ名は上の一覧だけ。それ以外の名前は書かない。」
- **未知のポーズ名・範囲外の `at`・配列でない値が来ても落とさない。** 無視する。

### 時刻への換算

`at` を秒に直すのは、**口の動きに使っている既存の時間軸と同じもの**を使う：
`moraPerSec`（既定 7.4、実測で適応）と、読みの総モーラ数から総発話時間を出し、
`at × 総発話時間` が手ぶりの開始時刻。
**文字数で換算しない**（漢字かな混じりでは文字数と発話時間が合わない）。
手は開始の約350ms前から上げ始め、言葉に間に合うようにする。

## 較正（位置合わせ）画面

手の位置は絵ごとに違うので、**設定欄に較正画面を作る。**

- 各ポーズについて、手の「基準点」（手首の中心）を、タイル上でドラッグして決める。
- 値は**元画像（base）のピクセル単位**で保存する（`localStorage`）。
  **割合（0..1）で保存しない**——x は幅に対する割合、y は高さに対する割合で、
  縦長画像では混ぜると 1.5 倍ずれる（顔の帯で実際に起きた不具合）。
- 位置・拡大率・左右反転の有無を、ポーズごとに調整・保存できる。
- 「このポーズを再生」ボタンで、登場→手ぶり→退場を確認できる。
- **画像からの自動検出はしない。** 手で決める。悪い値を黙って使わない。
- 座標変換は**1つの関数**（画像座標⇄画面座標）に集約する。
  描画側と較正側で別々に計算しない（ズレの原因）。

## 既知の落とし穴（顔で実際に起きたもの。手でも同じことが起きる）

1. **半透明で重ねると二重写しになる。** 不透明度で量を表さない。カットする。
2. **単位の混同。** x は幅比、y は高さ比。ピクセルで保存・計算する。
3. **画像の縁を羽毛化するとき、特徴の手前（約86%以降）から薄くする。**
   68% あたりから薄くすると、目や手の本体まで薄くなる。
4. **`speechSynthesis.cancel()` は `onend` を発火させる。** 発話ごとに通し番号を持たせ、
   古い発話の終了は無視する。手の退場もこの通し番号で守る。
5. **`rec.start()` を二重に呼ばない。** 起動中フラグで守る。
6. iOS は発話後、認識再開まで **約350ms** 置く。
7. **自分の声を拾わない。** 発話中と直後 0.9 秒の認識結果は捨てる。
8. ズーム・ピンチ操作では、点を中心に拡大するとき**オフセットを解く**
   （中央配置の画像に、隅基準の式を使わない）。
9. iPhone はキーボードが画面を覆うがリサイズされない。
   `visualViewport`（`kb = innerHeight − vv.height − vv.offsetTop`）で、顔と入力欄を固定する。

## 付録A：Gemini に手のスプライトを作らせる指示（Ken さんが Gemini に貼る）

**1ポーズずつ、別々の会話で作ってください。** 一度に複数を頼むと、

```
添付した澪の画像と同じ画風（アニメ調、同じ線の太さ、同じ肌の色、同じ塗り方）で、
右手の前腕から指先までだけを描いてください。

ポーズ：【ここにポーズを書く。例：手のひらを上に向けて、前に差し出している】

条件：
・背景は純粋な緑（#00FF00）、一色で平らに塗る。影やグラデーションは付けない。
・手と前腕だけ。体・顔・服の他の部分は描かない。袖は付けてよいが、緑と同じ色は使わない。
・前腕の途中（肘の手前）で、画像の下端で切れるようにする。
・手は画像の中央〜上寄りに置く。画像の縁に指先が触れない余白を取る。
・正面から見た向き。手の甲側か手のひら側かをポーズ名に合わせる。
・肌に緑色を混ぜない。輪郭線は肌に合う濃い茶色にする。

```

ポーズの書き方（【】に入れる文）：

| 名前 | 書く文 |
|---|---|

| `palm_up` | 手のひらを上に向けて、前に差し出している |
| `point_self` | 人差し指で、自分の胸（手前）を指している |
| `index_up` | 人差し指を一本、まっすぐ上に立てている。他の指は軽く握る |
| `think_finger` | 人差し指を、顎に軽く当てている |
| `gassho` | 手のひらを合わせている（右手のみ。左手は反転で作る） |

## 1. 総評 — 設計は高品質でした

**方針・情報階層・トーンは、依頼書の意図を正確に汲んでいました。** 特に次の判断が優れています。

| 良かった点 | 評価 |
|---|---|
| 「今日のブースト」を**学習開始ボタンより下**に配置 | 「勉強が主役」の原則に忠実。最重要の判断 |
| **ガチャ・ランダム報酬・連続ログインの罰・赤い未読バッジを明示的に排除** | 依頼していない配慮。ダークパターンの回避として的確 |
| 外貨損益をバーの長さと色で分解し、「損した」と**文章で断定** | 「利用者に計算を委ねない」という設計思想が良い |
| 未解放Lvを「押せないボタン」にせず**情報カード**にする判断 | 「未実装ボタンを置かない」制約への正しい解 |
| Lv解禁の判定を**起動直後に割り込ませない** | 学習の妨げを避ける配慮 |
| 色だけに依存せず符号・語句を併用 | アクセシビリティ配慮 |
| 実装前の要確認事項3点を**自ら明示** | 推測で埋めない姿勢は正しい |

**実機幅での描画検査も全項目合格でした**(下記6章)。

## 2. 最大の学び — 設計書とモックで欠けている項目が違っていた

確定設計(`FEATURE_SPEC_v4.md`)と機械的に突き合わせた結果、**2つの成果物の間に不整合**がありました。

| 分類 | 件数 | 具体例 |
|---|---|---|
| **A. 設計書にないがモックにはある** | 2件 | 受験科目の選択 / フィーバーの週1回制限 |
| **B. 名前だけで実体がない** | 2件 | 海外ショップ / 志望学部の設定UI |
| **C. 両方に無い** | 5件 | ふるさとクエスト / リカバリー / BP日次上限 / 非受験科目上限 / 全ジャンル制覇 |
| **D. 設計書にあるがモックにない** | 2件 | 分割購入比較 / 信用スコア詳細 |

### A の詳細(記載漏れ)

モックには実装されていたのに、設計書に書かれていませんでした。

- **受験科目の選択** — 設定画面に「科目設定 / 私立大学の受験科目を選択」として実装済み
- **フィーバーの週1回制限** — ショップに「30分だけ10倍・週1回」と明記済み

### D の詳細(設計のみで未実装)

設計書のモーダル一覧に記載があるのに、モックに実装がありませんでした。

- **分割購入比較**(「一括、分割回数、手数料差」と記載) — モックに「分割」「一括」「手数料」の文字が0件
- **信用スコア詳細**(「現在値、履歴、特典、停止条件」と記載) — モックに0件

### 次回への提案

**設計書とモックを作り終えたあと、両者を突き合わせる自己チェックを1回入れる**と、
この種の不整合は防げます。特に「モーダル一覧に書いたものが、全部モックに存在するか」の
機械的な確認が有効です。

## 3. 設計判断として変更した点(1件)

### 集中モードで「コーチ」タブごと隠す設計を変更しました

あなたの設計では、集中モード中に**世界タブとコーチタブの両方**を非表示にしていました。
しかし**コーチ画面には既存 ver.3.3.0 の機能が含まれています**。

| コーチ画面の機能 | 種別 | 変更後の扱い |
|---|---|---|
| ポーズ変更 | 既存 | 残す |
| メッセージ(端末内コーチ) | 既存 | 残す |
| **🤖 AIに聞く** | 既存 | **必ず残す** |
| 装備 / ショップ / 仲間 | ver.4 新規 | 隠す |

**理由**: 親の当初要望は「**金融・ショップ機能**が自動でOFF」であり、コーチ画面全体ではありません。
特に「AIに聞く」は、**受験直前こそ小論文・面接の相談に使いたい機能**です。

**変更後**: 集中モードは **5タブ**(今日/記録/グラフ/**コーチ**/設定)。
隠すのは世界タブと、コーチ内の装備・ショップ・仲間カードのみ。

### 次回への提案

**既存機能と新規機能が同じ画面に同居する場合、「隠す」対象を画面単位ではなくカード単位で指定する**と、
既存機能を巻き込む事故を防げます。

## 5. 確定した仕様(あなたが「要確認」とした3点を含む)

あなたが実装前の確認事項として挙げた3点は、いずれも的確な指摘でした。親の判断で以下に確定しました。

| # | 項目 | 決定 |
|---|---|---|
| 1 | 通常倍率3.0倍とフィーバー10倍の関係 | **置換方式**。フィーバー中は他の倍率を無効化し10倍固定(掛け算だと30倍で経済が壊れるため) |
| 2 | GT → 円の換算式 | **1 GT = 100円**を基準とし、為替で±20%まで変動。**月間上限は円建てで2,000円に固定**(親の支出は為替に影響されない) |
| 3 | 52倍速での定期預金の期間 | **1ヶ月定期=4週ロック / 3ヶ月定期=12週ロック** |
| 4 | タブ構成 | **6タブを採用**(あなたの案どおり)。320px幅で成立することを実測で確認 |
| 5 | 集中モード | **コーチタブを残す**(3章の変更) |
| 6 | 科目フィルタ | **採用** |
| 7 | 実装の着手順 | **ニュース → ポイント基礎 → 金融**(公募推薦が10・11月のため) |

## 7. 補完した9項目(Claude実施済み・再作業不要)

B・C・D の計9件を Claude が補完し、モックにも実装しました。
詳細は [`../design/GUI_SPEC_v4_ADDENDUM.md`](../design/GUI_SPEC_v4_ADDENDUM.md) を参照してください。

| # | 補完項目 | 実装場所 |
|---|---|---|
| B-1 | **海外ショップ**(国内/海外の切替・同一商品を両方に配置・為替注記) | shop-modal |
| B-2 | **志望学部の設定UI**(経済/法/国際の複数選択) | 設定 + faculty-modal |
| C-1 | **ふるさとクエスト**(5クエスト・進捗表示) | 世界タブ + furusato-modal |
| C-2 | 消費アイテム**リカバリー** | shop-modal |
| C-3 | BP獲得の1日上限 1,500BP | boost-modal |
| C-4 | 非受験科目・読書の1日100BP上限 | boost-modal + 設定 |
| C-5 | 全ジャンル制覇 +200BP | 世界タブ |
| D-1 | **分割購入比較**(一括/3/6/12回の総額を並記) | purchase-modal |
| D-2 | **信用スコア詳細**(履歴・特典・停止条件) | credit-modal |

補完後も **390px/320px 横あふれなし・44px未満0件・JSエラーなし** を再確認済み。
ボタン総数は 97 → 119 に増加。

### B-1(海外ショップ)を最重要とした理由

これが無いと、**「円高だと海外が安くなる」という為替学習の中核体験が成立しません**。
同一商品(フェドーラハット)を国内3,000BP / 海外20BDの両方に置き、
円高時の差額を明示することで初めて学びになります。

## 8. 次回の依頼に向けて

このプロジェクトで機能する進め方が固まってきました。

1. **成果物はzipにまとめて渡す。** テキストのコピー&ペーストでは空行が欠落することが実測で判明しました
2. **設計書とモックの整合を、提出前に自己チェックする**(2章)
3. **既存機能を巻き込まない**。隠す・変える対象は画面単位ではなくカード単位で指定する(3章)
4. **確定設計に列挙された項目を、チェックリストとして機械的に消し込む**。
   `FEATURE_SPEC_v4.md` の各章の機能名を1つずつ確認すれば、C群の5件は防げました
5. 実機幅の描画検査は Claude が代行できます。**あなたはHTMLの構造と設計判断に集中してください**

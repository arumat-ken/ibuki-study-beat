# AI連携プロトコル — Codex × Claude

このリポジトリで複数のAIが役割分担して開発するための取り決め。
**AIも人間も、このファイルのルールに従うこと。**

---

## 1. 誰が何をするか

| 担当 | 役割 | 使うブランチ |
|---|---|---|
| **Codex**(OpenAI) | 画面設計・UIモックアップ・デザイン提案 | `codex/*` |
| **Claude**(Anthropic) | 計算ロジック・データ構造・実装・テスト・リリース | `claude/*` |
| **親**(arumat-ken) | 仕様の決定・優先順位・予算・最終承認 | `main` へのマージ承認 |

**原則: 自分の担当ブランチにだけ push する。相手のブランチを直接書き換えない。**
`main` は両者の成果が合流する場所であり、直接pushしない(PR経由)。

---

## 2. 受け渡しの方法(3つのルート)

### ルートA: Codex が直接コミットする 【推奨・自動】

```
Codex が codex/* ブランチを作成
   → 成果物をコミット
   → main 宛の Pull Request を作成
   → Claude が PR を購読していれば自動的に気づく
   → Claude がレビュー・コメント・修正を push
   → 親が承認してマージ
```

**必要な設定**(親が一度だけ行う):
1. ChatGPTデスクトップアプリで Codex をセットアップ
2. Codex の GitHub App に、本リポジトリへの **write 権限**を付与
3. 対象リポジトリとして `arumat-ken/ibuki-study-beat` を選択

### ルートB: チャット版ChatGPTの出力を、人が保存する 【手動】

チャット版ChatGPTには**書き込み権限が構造的にありません**(読み取り専用)。
出力は人が次のいずれかで運びます。

- GitHubのWeb画面から貼り付けてコミット
- Claudeとのチャットに貼り付け(Claudeが代わりにコミットする)
- ファイルとしてClaudeのチャットに添付

### ルートC: 読み取りだけ共有する 【常時有効】

本リポジトリは公開されているため、**どのAIでも読める**。
URLを渡すだけで前提知識を共有できる(設定不要)。

```
https://raw.githubusercontent.com/arumat-ken/ibuki-study-beat/main/<パス>
```

## 4. 引き渡しの合図

作業が終わったら、**必ず次のいずれかで合図する**。合図がないと相手は気づかない。

| 合図の方法 | 使う場面 |
|---|---|
| **Pull Request を作成する** | 最も確実。Claudeは購読していれば自動で気づく |
| `docs/exchange/STATUS.md` を更新してコミット | 軽微な更新 |
| コミットメッセージの先頭に `[handoff]` を付ける | 相手に読んでほしいコミット |
| 親が相手に口頭で伝える | 上記が使えないとき |

## 5. 守るべき境界(両AI共通)

これを破ると、相手の作業が壊れます。

1. **アプリ本体を、担当外のAIが勝手に書き換えない**
   `index.html` / `css/app.css` / `js/*.js` / `sw.js` を変更してよいのは **Claude のみ**。
   Codexは `docs/` 配下(設計書・モック)にとどめる。
2. **localStorage の保存キー `ibukiStudyBeat.v3` を絶対に変えない**
   変えると伊吹さんの過去の学習記録がすべて読めなくなる。
3. **リリース時は `js/app.js` の `APP_VERSION` と `sw.js` の `CACHE` を必ず同時に上げる**
   片方だけだと新版が利用者に届かない。
4. **凍結仕様を変更しない**(`docs/design/APP_CONTEXT.md` の末尾に一覧)
   グラフ画面の構造、黒×ゴールドの世界観、外部通信ゼロ、5画面の役割。
5. **`main` に直接 push しない**(PR経由。ただし親の判断による例外は可)
6. **確定していない仕様を推測で埋めない**。「要確認」と明記して親に判断を仰ぐ。
7. **新しい専門用語・略語・記号を使う時は、`docs/GLOSSARY.md`を先に更新する**
   意味、このアプリでの役割、具体例、誤解しやすい点を一項目で説明する。別の資料を読まないと分からない説明にしない。

---

## 6. 判断が割れたときの優先順位

1. **親(arumat-ken)の指示** — 最優先
2. **凍結仕様**(`APP_CONTEXT.md`)
3. **確定設計**(`FEATURE_SPEC_v4.md`)
4. **このアプリの原則** ↓
5. 各AIの提案

> **原則: このアプリの主役は「毎日の受験勉強時間の確保と、その見える化」。**
> ポイント・ショップ・金融は勉強を続けるための燃料であって、主役ではない。
> アプリを開いた瞬間に目に入るべきは「今日やること」と「学習を開始する ▶」。
> **これに反する設計は、どれだけ魅力的でも採用しない。**

## 7. Claude 側の自動化(実装済みの能力)

Claudeは次のことができる。Codex側の担当者はこれを前提にしてよい。

- リポジトリの**全ファイルを直接読む**
- **PR の活動を購読**し、コメント・CI失敗・レビューをWebhookで受け取って自動的に反応する
- HTMLモックを **Playwrightで実際にレンダリングし、iPhone幅(390px)と320px幅で
  スクリーンショットを撮って**、レイアウト崩れ・横あふれ・タップ領域・JSエラーを検査する
- 単体テスト(`node --test`)と受け入れ試験(Playwright・69項目)を実行する
- GitHub Pages へのリリース(`main` へのマージで約1分後に自動配信)

**Claudeにできないこと**: 自分から定期的にリポジトリを見に行くことはできない。
親から声がかかるか、購読中のPRにイベントが起きたときに動く。

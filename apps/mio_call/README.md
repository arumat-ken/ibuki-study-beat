# Mio Call — 第1段（ズーム対談スタイル）

公開先: https://claude.ai/code/artifact/d217648b-1661-4305-a6cf-10bc7569f79b

澪と声で会話する。バストアップ正面の1枚を顔として使い、口だけを動かす。

## なぜこの構成か

「コストフリーで GPT-Live 相当の音声会話」という条件に対して、
追加のAPI契約が要る部品を1つも使わない構成にした。

| 役 | 使うもの | 追加費用 |
|---|---|---|
| 耳 | 端末の音声認識（`webkitSpeechRecognition`, ja-JP） | なし。iOS/Safari に内蔵 |
| 頭脳 | Artifact の `sample` 機能から Claude を呼ぶ | なし。閲覧者自身の Claude 使用量を使う |
| 声 | 端末の読み上げ（`speechSynthesis`, ja-JP） | なし。iOS/Safari に内蔵 |
| 顔 | 参照シートのバストアップ正面（端末内に保存） | なし |

OpenAI Realtime API を使う道は、月額でも従量でも必ず課金が発生する。
第1段では会話が成立するかどうかを確かめたいだけなので、課金のある部品を外した。
Realtime API に移るのは、この構成で会話が成立してから判断すればよい。

なお `sample` は Ken さんの Claude 使用量を消費する。無料なのは「別途の請求が増えない」
という意味であって、消費量がゼロという意味ではない。

## 口の動かし方

音量ではなく**読みがな**で動かしている。

返事は JSON で受け取る:

```json
{"reply": "話す文", "kana": "よみがな", "emotion": "happy"}
```

`kana` を5母音（あいうえお）＋ん＋閉じ、の7つの口の形に変換して順に出す。
日本語は1拍1母音なので、これで形が合う。漢字の読みはブラウザでは分からないため、
返事と一緒に読みを返させている。

- 小さい「ゃゅょ」と小書き母音は前の拍に乗る（「きょう」は2拍で「お・う」）
- 長音「ー」は直前の母音を保つ
- 「っ」と句読点は口を閉じる

開くのは 45ms、閉じるのは 85ms の非対称で補間する。設計書の `lipsync.py` と同じ考え方。

話す速さは端末の声によって違うので、1回話すごとに実測して次回に反映する（初期値 7.4拍/秒）。

## 顔の差し替えと口の位置

### 表情は「組み合わせ表」であって「絵の一覧」ではない

感情6 × 強さ3 × 視線5 × 涙2 を絵で持つと 180 枚になり、全部を同じ顔に保つことが
そもそも不可能になる。掛け算になるのは「顔まるごと」を持つからで、**層で持てば足し算**になる。

| | 掛け算（顔ごと） | 足し算（層ごと） |
|---|---|---|
| 感情6・強さ3・涙2 | 36枚 | **7枚** |
| 視線5 を足す | 180枚 | 7枚（+視線は将来コードで） |

いま持つ枠は8つ。

- **通常** — これだけで会話できる
- **目**：閉じた目 / 笑う目 / 見開く目 / 潤んだ目
- **眉**：上げ眉 / 困り眉 / 怒り眉

各画像は顔全体で作ってよい。使うのは目の帯・眉の帯だけで、切り出しは自動。

- **強さ**は絵ではなく**重ねる濃さ**で出す。弱い笑顔＝笑う目を45%で重ねる。
- **涙**は絵ではなく**コードで描く**。静止画では「潤んでいる」までしか出せず、
  流れる涙は描いて動かすしかない。潤んだ目の絵に、流れる筋と粒を重ねる。
- **まばたき**は閉じた目の枠へのクロスフェード（閉じ70ms・保持50ms・開き100ms）。
- 目と眉は別々に補間する。眉が先に決まって目が後から届いてよい。
  同じ帯で絵を入れ替えるときは一度0まで薄くするので、2つの目が同時に出ることはない。

### 帯の位置

「目の位置を合わせる」で左目・右目の中心をタップすると、両目の間隔を基準に帯を決める。

- 眉の帯：目の中心の 0.82〜0.26 間隔ぶん上
- 目の帯：0.26 上 〜 0.32 下

眉は目の中心の 0.3〜0.45 間隔ぶん上にあるので、この範囲に入る。
2つの帯は重ねない。重ねると、上に来た層が下の層の特徴を塗り戻してしまう。

読み込んだ画像は 640px に縮小して端末内（`localStorage`）に保存する。どこにも送信しない。
端末ごとの保存なので、iPhone と Mac では別々に選ぶ。

### 口の大きさと「隠す範囲」は別

この2つを1つの数値で兼ねていたため、口を小さくすると元の絵の口がはみ出していた。いまは別。

- **口の大きさ** — 描く口の寸法
- **隠す範囲** — 元の絵の口を覆うパッチの半径

「口の位置を合わせる」で口の中心をタップすると、**隠す範囲は自動で測る**。
中心のまわりで、周囲の肌より明らかに暗い画素（＝唇の線）を集め、
中心からの距離の94パーセンタイルを取り、1.65倍する。
パッチは半径の74%までは完全に不透明なので、測った端は必ず不透明な内側に入る。
外れたときはスライダーで直せる。

## 分かっている制約

- 画面ロックやアプリ切替で音声認識も読み上げも止まる（iOS の仕様）。切り替え時に明示的に停止している。
- 読み上げ中は聞き取りを止める。自分の声を拾ってしまうため。
- `emotion` は受け取って記録しているが、まだ表情の切り替えには使っていない。
  表情ごとの画像が揃った時点で、ここに繋ぐ。
- 音声認識が使えない端末では、文字入力欄から送れる。

## 実物での検証結果（2026-09-07）

澪のバストアップ2枚（目を開いた通常／目を閉じた絵）を実際に通した記録。

| 工程 | 結果 |
|---|---|
| 2枚の位置合わせ | 倍率 1.00・残差 4.1（同じ構図） / 34ms |
| 目の位置の自動検出 | 検出成功。間隔は画像幅の23.4% |
| 口の測定 | 半幅37px・高さ19px → 口の大きさ93px・隠す範囲59px（画像幅の9.2%） |
| まばたき | 12秒で1コマ6段階の急変を検出。動いている |

`mouth_on_mio.png` が彼女の顔に実際に描いた口（閉じ／あ／い／お）、
`blink_on_mio.png` がまばたきの途中のコマ。

### ここで見つかった不具合

- **`fitCanvas` が未定義**。直前の変更で定義ごと消していた。起動時に例外が出て、
  アニメーションの開始と Claude への接続がまとめて止まっていた。
  以後、起動時の例外は画面の記録に出る。
- **口の測定が髪を拾っていた**。基準の暗さを「窓の中で一番暗い画素」から取っていたため、
  ほぼ黒の髪が窓に入ると基準がそちらに引きずられ、唇より暗いものしか拾わなくなっていた。
  タップした場所そのものの暗さを基準にするよう変更。
- **測り方が範囲の百分位だった**。鼻の影や髪など、口とつながっていない暗い部分まで
  口の一部として数えていた。タップ地点から暗い連なりを外へ辿る方式に変更。
- **描く口の大きさが実物と合っていなかった**。元の口を隠すだけになり、口が消えていた。
  測った半幅から自動で決めるようにした。

## 澪の顔はページに入っている

通常と閉じた目の2枚は、560px の JPEG としてページに埋め込んである（各72KB）。
読み込む操作も位置合わせも要らず、開けばその顔で話す。まばたきもする。

測ってある値も一緒に入れてある（口の中心 0.505 / 0.4296、口の大きさ93px、隠す範囲59px）。
端末に前の設定が残っていても、自分の絵を入れていなければ内蔵の値で上書きする。
前の絵はもう無いのだから、それに合わせた設定を残しても意味がないため。
自分で調整したあとは `mio.calFor=builtin` の印が付き、以後は調整のほうを残す。

枠を押せば別の絵に差し替えられる。「最初の顔に戻す」で内蔵の顔に戻る。

# Mio Rig Bench

Mio の実行時の作りを、APIキーなし・課金なしで実機検証するための1ファイルの Web アプリ。

公開先: https://claude.ai/code/artifact/86c97924-8275-4924-a02e-c13b69b0eddf

## なぜ作ったか

Mio で未検証のまま残っていた4点は、3Dモデルが完成しなくても確かめられる。
先に確かめておけば、モデルが出来てから作り直す事態を避けられる。

1. iPhone Safari で WebGL のキャラクターが実用的な速度で出るか
2. 1本指の回転・2本指の拡大縮小と平行移動が、指の動きとして自然か
3. 音量から口を動かす計算が、実際の声で見られる動きになるか
4. 画面ロックやアプリ切替で `AudioContext` が止まるか（設計書で挙げた iOS の既知の危険）

4 は「イベント記録」に行が増えるかどうかで実測できる。

## 中身

- **仮の素体** — three.js のプリミティブで組んだ 7.5頭身の A ポーズ。
  参照シートと同じ配色（生成りのニット／ベージュの巻きスカート／濃茶の髪）、
  背景も参照シートと同じ `#808080`。顔は Canvas テクスチャで、表情と口の開きを毎フレーム描き直す。
- **視点の慣性** — 指数減衰の積分。`camera.py` と同じ式なので、
  60fps でも 30fps でも同じ角度だけ回る。
- **口の同期** — RMS → dBFS → 非対称平滑（開く 25ms／閉じる 110ms）→ ヒステリシス。
  `lipsync.py` と同じ計算を JavaScript に移したもの。適応ピーク正規化には下限を置いて、
  無音のときに増幅が暴走しないようにしてある。
- **GLB 受け入れ判定** — ローカルの GLB を読み込み、下の3項目を自動で埋める。

## GLB の判定項目

画像から3Dを起こしたら、そのファイルを「GLBを読み込む」で読ませる。

| 項目 | 通る条件 | 落ちたときの意味 |
|---|---|---|
| 顔が崩れていない | メッシュが読めて三角形が200個以上 | ファイルが壊れている／変換に失敗している |
| 上下の服が別々のメッシュ | メッシュ3個以上、またはマテリアル3種以上 | 着せ替えができない。モデリングからやり直し |
| 腕と体がくっついていない | 横幅 / 身長 > 0.30 | 腕が胴に埋まっている。A ポーズの参照画像が効いていない |

2番目が最重要。着せ替えは後付けの機能ではなく、モデルを作る時点の構造で決まる。

## ファイルの読み込みについて

GLB は `FileReader` で ArrayBuffer にしてから `GLTFLoader.parse()` に渡している。
ネットワークを一切使わないので、公開先のサンドボックスに阻まれない。
`GLTFLoader.load()` を使うと URL の取得が発生して失敗する。

## 通信が遮られている場合

three.js は CDN から読み込む。取得できない回線では 3D は出ないが、
表情の切り替え・診断・イベント記録は動き続ける。
「イベント記録」に理由が出る。
